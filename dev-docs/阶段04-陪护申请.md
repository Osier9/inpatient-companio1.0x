# 阶段 04 陪护申请开发文档

## 1. 开发目标

实现家属选择护工并提交陪护申请，管理员查看申请详情并确认、驳回或调整申请。确认后生成服务单。

## 2. 输入与依赖

- 依赖阶段：阶段 02、阶段 03。
- 需求来源：BF-001 至 BF-008、FAM-005、ADM-005。

## 3. 数据库开发

新增迁移：`V005__care_request.sql`。

创建表：

- `care_request`
- `care_service_order`

关键索引：

- `idx_care_request_status(request_status)`
- `idx_care_request_patient(patient_id)`
- `idx_care_request_family(family_user_id)`
- `idx_service_order_status(service_status)`
- `idx_service_order_patient(patient_id)`
- `idx_service_order_caregiver(caregiver_id)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `FamilyCareRequestController` | 家属提交、取消、查看申请 |
| `CareRequestAdminController` | 管理员申请列表、详情、审核 |
| `CareRequestApplicationService` | 申请创建、确认、驳回 |
| `CareServiceOrderService` | 创建服务单 |
| `CareRequestDomainService` | 状态流转和权限规则 |

### 4.2 业务规则

- 家属只能为已授权患者提交申请。
- 结束日期不能早于开始日期。
- 提交后状态为 `PENDING`。
- 待审核申请可由家属取消。
- 管理员确认时可调整最终护工、服务日期、班次。
- 管理员驳回必须填写原因。
- 确认申请后创建服务单，服务单初始状态为 `PENDING` 或按日期判断 `SERVING`。

## 5. API 开发

必须实现：

- `POST /api/family/care-requests`
- `GET /api/family/care-requests`
- `GET /api/family/care-requests/{id}`
- `POST /api/family/care-requests/{id}/cancel`
- `GET /api/admin/care-requests`
- `GET /api/admin/care-requests/{id}`
- `POST /api/admin/care-requests/{id}/approve`
- `POST /api/admin/care-requests/{id}/reject`

## 6. 前端开发

### 6.1 家属端

- 护工详情页主按钮：申请陪护。
- 申请表单字段：
  - 患者、目标护工、开始日期、结束日期、班次、需求说明。
- 我的申请页展示状态：
  - 待审核、已确认、已驳回、已取消。
- 驳回状态展示审核意见。

### 6.2 管理端

- 申请列表：
  - 申请编号、患者、家属、目标护工、期望日期、班次、状态、提交时间。
- 申请详情：
  - 患者信息、家属信息、护工信息、需求说明。
- 审核弹窗：
  - 确认：最终护工、服务日期、班次、备注。
  - 驳回：驳回原因。

## 7. 联调步骤

1. 家属选择患者和护工提交申请。
2. 管理员查看待审核申请。
3. 管理员确认申请。
4. 数据库生成服务单。
5. 家属端申请状态变更为已确认。
6. 再提交一条申请并驳回，确认家属端可见原因。

## 8. 验收标准

- 未授权患者不可提交申请。
- 申请确认后生成服务单。
- 申请驳回必须有原因。
- 家属端可查看申请状态。
