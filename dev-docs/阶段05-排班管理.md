# 阶段 05 排班管理开发文档

## 1. 开发目标

实现服务单排班、排班冲突校验、排班调整、管理员排班日历、家属端排班查看和护工端今日/周月排班查看。

## 2. 输入与依赖

- 依赖阶段：阶段 04。
- 需求来源：BF-009 至 BF-013、ADM-006、CAR-002、CAR-008。

## 3. 数据库开发

新增迁移：`V006__schedule.sql`。

创建表：

- `care_schedule`

关键约束：

- 唯一约束：`caregiver_id + schedule_date + shift_type + deleted`。

关键索引：

- `idx_schedule_order(service_order_id)`
- `idx_schedule_patient(patient_id, schedule_date)`
- `idx_schedule_caregiver(caregiver_id, schedule_date)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `ScheduleAdminController` | 管理员排班维护 |
| `FamilyScheduleController` | 家属查看患者排班 |
| `CaregiverScheduleController` | 护工查看本人排班 |
| `ScheduleApplicationService` | 新增、调整、取消排班 |
| `ScheduleDomainService` | 日期范围、服务单状态、冲突校验 |

### 4.2 业务规则

- 排班必须关联服务单、患者、护工。
- 排班日期必须落在服务单日期范围内。
- 已结束或已中止服务单不可新增排班。
- 同一护工同一日期同一班次不可重复排班。
- 排班调整成功后发布排班变更事件。

## 5. API 开发

必须实现：

- `GET /api/admin/schedules`
- `POST /api/admin/schedules`
- `PUT /api/admin/schedules/{id}`
- `DELETE /api/admin/schedules/{id}`
- `GET /api/family/patients/{patientId}/schedules`
- `GET /api/caregiver/schedules`
- `GET /api/caregiver/schedules/today`

## 6. 前端开发

### 6.1 管理端

- 排班页支持日历/列表切换。
- 筛选条件：日期、护工、患者、班次、服务状态。
- 排班卡片展示：护工、患者、班次、服务状态。
- 新增/调整排班弹窗。
- 冲突提示需展示冲突护工、日期、班次和患者。

### 6.2 家属端

- 首页当前服务卡片展示当前护工和班次。
- 患者排班页按日期展示服务安排。

### 6.3 护工端

- 今日页展示今日患者、医院、科室、床号、护理注意事项。
- 排班页支持周视图/月视图。

## 7. 联调步骤

1. 管理员为服务单创建排班。
2. 家属端查看患者排班。
3. 护工端查看今日排班。
4. 管理员创建冲突排班。
5. 系统阻止保存并提示冲突。

## 8. 验收标准

- 排班冲突不可保存。
- 家属只能查看授权患者排班。
- 护工只能查看本人排班。
- 已结束服务单不可新增排班。
