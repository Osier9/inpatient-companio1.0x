# 阶段 06 陪护任务管理开发文档

## 1. 开发目标

实现固定任务模板、服务单任务初始化、家属自定义任务、护工确认/退回/建议调整，以及护工临时任务。

## 2. 输入与依赖

- 依赖阶段：阶段 05。
- 需求来源：BF-014 至 BF-022、FAM-006、FAM-007、CAR-003、CAR-004、CAR-006。

## 3. 数据库开发

新增迁移：`V007__care_task.sql`。

创建表：

- `care_task_template`
- `care_task`

关键索引：

- `idx_task_patient(patient_id, planned_at)`
- `idx_task_caregiver(caregiver_id, planned_at)`
- `idx_task_status(task_status)`
- `idx_task_order(service_order_id)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `TaskTemplateAdminController` | 固定任务模板维护 |
| `FamilyTaskController` | 家属查看任务、添加自定义任务 |
| `CaregiverTaskController` | 护工任务清单、确认、退回、临时任务 |
| `TaskTemplateService` | 模板 CRUD |
| `CareTaskApplicationService` | 任务创建和状态操作 |
| `CareTaskDomainService` | 任务权限和状态流转 |
| `TaskInitializationService` | 服务单任务初始化 |

### 4.2 业务规则

- 启用模板才参与服务单任务初始化。
- 家属新增任务必须属于服务中的授权患者。
- 家属新增自定义任务状态为 `PENDING_CONFIRM`。
- 护工确认后任务状态变为 `PENDING_EXECUTE`。
- 护工建议调整时状态变为 `NEED_ADJUST`，必须填写原因。
- 护工退回时必须填写原因。
- 护工临时任务直接进入可执行/可记录状态，并对家属可见。
- 自定义任务页面必须提示“请以医护人员医嘱为准”。

## 5. API 开发

必须实现：

- `GET /api/admin/task-templates`
- `POST /api/admin/task-templates`
- `PUT /api/admin/task-templates/{id}`
- `PATCH /api/admin/task-templates/{id}/enabled`
- `GET /api/family/patients/{patientId}/tasks`
- `POST /api/family/tasks`
- `GET /api/caregiver/tasks`
- `POST /api/caregiver/tasks/{id}/confirm`
- `POST /api/caregiver/tasks/{id}/adjust`
- `POST /api/caregiver/tasks/{id}/reject`
- `POST /api/caregiver/tasks/temp`

## 6. 前端开发

### 6.1 管理端

- 任务模板列表。
- 新增/编辑模板弹窗：
  - 任务名称、任务类型、默认执行时间、执行要求、是否启用。

### 6.2 家属端

- 任务计划页：
  - 按日期展示任务。
  - 展示任务来源、计划时间、执行方式、状态。
- 添加自定义任务页：
  - 任务名称、执行时间、执行方式、备注。
  - 医嘱提示文案。

### 6.3 护工端

- 任务清单按状态分组：
  - 待确认、待执行、已完成、已超时。
- 待确认任务操作：
  - 确认、建议调整、退回。
- 临时任务入口：
  - 任务名称、执行时间、执行方式、备注。

## 7. 联调步骤

1. 管理员新增固定任务模板。
2. 管理员确认服务单后初始化任务。
3. 家属查看任务计划。
4. 家属新增自定义任务。
5. 护工确认该任务。
6. 家属端任务状态同步变为待执行。

## 8. 验收标准

- 固定任务可由模板生成。
- 家属自定义任务需护工确认。
- 退回/调整必须填写原因。
- 护工临时任务对家属可见。
