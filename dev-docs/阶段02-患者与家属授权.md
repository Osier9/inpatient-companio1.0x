# 阶段 02 患者与家属授权开发文档

## 1. 开发目标

实现患者资料管理、家属账号创建、患者与家属授权绑定，并建立后续模块复用的数据权限校验能力。

## 2. 输入与依赖

- 依赖阶段：阶段 01。
- 需求来源：ADM-003、ADM-004、EX-001、AC-010。
- 关键前置：`sys_user` 已支持 FAMILY 角色。

## 3. 数据库开发

新增迁移：`V003__patient_family.sql`。

创建表：

- `patient`
- `patient_family_auth`

关键索引：

- `idx_patient_name(name)`
- `idx_patient_location(hospital, department, bed_no)`
- `uk_patient_family(patient_id, family_user_id, deleted)`
- `idx_family_user(family_user_id, auth_status)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `PatientAdminController` | 后台患者新增、编辑、详情、列表 |
| `FamilyAuthAdminController` | 家属绑定、授权启停 |
| `FamilyPatientController` | 家属端查询授权患者 |
| `PatientApplicationService` | 患者资料维护 |
| `FamilyAuthApplicationService` | 创建家属账号并绑定授权 |
| `PatientAccessService` | 家属患者权限校验 |

### 4.2 业务规则

- 一个患者可绑定多个家属。
- 一个家属可绑定多个患者。
- 同一患者和同一家属不能重复有效绑定。
- 管理员绑定手机号不存在的家属时，自动创建 FAMILY 账号。
- 授权停用后，家属不可查看该患者任何业务数据。

## 5. API 开发

必须实现：

- `GET /api/admin/patients`
- `POST /api/admin/patients`
- `GET /api/admin/patients/{id}`
- `PUT /api/admin/patients/{id}`
- `POST /api/admin/patients/{id}/family-auths`
- `PATCH /api/admin/family-auths/{id}/status`
- `GET /api/family/patients`
- `GET /api/family/patients/{id}`

## 6. 前端开发

### 6.1 管理端

- 患者列表页：
  - 搜索：患者姓名、医院、科室、床号、服务状态。
  - 表格：姓名、性别、年龄、医院、科室、床号、授权家属数、当前服务状态。
- 患者详情页：
  - 基础信息。
  - 护理注意事项。
  - 授权家属列表。
  - 绑定家属按钮。
- 绑定家属弹窗：
  - 家属姓名、手机号、关系、初始密码。

### 6.2 家属端

- 首页患者切换组件。
- 无授权患者空状态：
  - 文案：暂无授权患者，请联系陪护机构管理员绑定。

## 7. 联调步骤

1. 管理员新增患者。
2. 管理员绑定新手机号家属。
3. 家属登录后查看授权患者列表。
4. 管理员停用授权。
5. 家属刷新患者列表，确认患者消失。

## 8. 验收标准

- 管理员可维护患者资料。
- 管理员可绑定和停用家属授权。
- 家属只能查看授权患者。
- `PatientAccessService` 可供后续模块调用。
