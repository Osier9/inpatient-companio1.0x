# 阶段 07 执行记录与图片开发文档

## 1. 开发目标

实现护工提交任务执行记录、图片上传、家属陪护记录时间线、管理员记录检索和任务超时标记。

## 2. 输入与依赖

- 依赖阶段：阶段 06。
- 需求来源：BF-023 至 BF-029、FAM-008、CAR-005、EX-007、EX-008。

## 3. 数据库开发

新增迁移：`V008__care_record.sql`。

创建表：

- `care_record`
- `care_record_image`

复用表：

- `file_object`

关键索引：

- `idx_record_task(task_id)`
- `idx_record_patient(patient_id, actual_executed_at)`
- `idx_record_caregiver(caregiver_id, actual_executed_at)`
- `idx_record_order(service_order_id)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `CaregiverRecordController` | 护工提交执行记录 |
| `FamilyRecordController` | 家属查看记录时间线和详情 |
| `AdminRecordController` | 管理员记录检索 |
| `ImageFileController` | 图片上传和签名 URL |
| `CareRecordApplicationService` | 提交记录、更新任务状态 |
| `CareRecordDomainService` | 校验任务是否可执行 |
| `TaskTimeoutJob` | 扫描并标记超时任务 |

### 4.2 业务规则

- 护工只能提交本人相关任务的记录。
- 执行状态包括 `COMPLETED` 和 `SKIPPED`。
- `SKIPPED` 必须填写原因。
- 图片最多 3 张。
- 单张图片不超过 10 MB。
- 支持 JPG、PNG。
- 记录提交成功后，任务状态更新为已完成或已跳过。
- 超过计划时间 30 分钟未提交的任务标记为已超时。

## 5. API 开发

必须实现：

- `POST /api/caregiver/tasks/{taskId}/records`
- `POST /api/common/files/images`
- `GET /api/common/files/{id}/signed-url`
- `GET /api/family/patients/{patientId}/records`
- `GET /api/family/records/{id}`
- `GET /api/admin/care-records`
- `GET /api/admin/care-records/{id}`

## 6. 前端开发

### 6.1 护工端

- 提交记录页：
  - 执行状态。
  - 实际执行时间。
  - 备注/跳过原因。
  - 图片上传。
- 图片上传组件：
  - 最多 3 张。
  - 支持预览和删除。
  - 上传失败保留表单内容。

### 6.2 家属端

- 陪护记录时间线：
  - 日期选择。
  - 任务名称、计划时间、实际执行时间、护工、状态、备注、图片。
- 图片预览：
  - 先请求签名 URL。
  - 无权限展示提示。

### 6.3 管理端

- 记录检索页：
  - 筛选：患者、护工、日期、任务状态。
  - 详情：记录信息、图片、提交时间。

## 7. 联调步骤

1. 护工打开待执行任务。
2. 提交已完成记录并上传图片。
3. 家属查看时间线和图片。
4. 管理员检索记录。
5. 创建一个过期未提交任务，等待定时任务标记超时。

## 8. 验收标准

- 图片数量和大小限制生效。
- 跳过任务必须填写原因。
- 家属只能查看授权患者记录。
- 未授权图片不可访问。
- 超时任务自动标记并可检索。
