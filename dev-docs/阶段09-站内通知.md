# 阶段 09 站内通知开发文档

## 1. 开发目标

实现站内通知列表、未读数、已读状态，以及关键业务事件触发通知。V1.0 不接入短信、微信模板消息或电话通知。

## 2. 输入与依赖

- 依赖阶段：阶段 04-08。
- 需求来源：站内通知、EX-006、NFR-002。

## 3. 数据库开发

新增迁移：`V010__notification.sql`。

创建表：

- `notification`

关键索引：

- `idx_notification_receiver(receiver_user_id, read_status)`
- `idx_notification_related(related_type, related_id)`
- `idx_notification_type(notification_type)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `NotificationController` | 通知列表、未读数、已读 |
| `NotificationApplicationService` | 创建通知、标记已读、刷新未读 |
| `NotificationEventListener` | 监听业务事件 |
| `NotificationDomainService` | 校验通知归属 |

### 4.2 事件来源

- 申请提交：通知管理员。
- 申请确认：通知家属、护工。
- 申请驳回：通知家属。
- 排班变更：通知家属、护工。
- 家属新增任务：通知护工。
- 任务调整/退回：通知家属。
- 任务超时：通知护工、管理员。
- 留言发送：通知接收方。
- 服务结束：通知家属评价。

## 5. API 开发

必须实现：

- `GET /api/common/notifications`
- `GET /api/common/notifications/unread-count`
- `POST /api/common/notifications/{id}/read`
- `POST /api/common/notifications/read-all`

## 6. 前端开发

### 6.1 管理端

- 顶部通知铃展示未读数。
- 通知列表展示标题、内容、类型、时间、已读状态。
- 点击通知跳转关联业务页面。

### 6.2 家属端

- 底部导航或标题栏展示红点。
- 申请确认、申请驳回、任务调整、留言回复、待评价需有通知。

### 6.3 护工端

- 任务待确认、排班变更、任务超时、家属留言需有通知。

## 7. 缓存设计

- Redis key：`notify:unread:{userId}`。
- 通知创建时未读数 +1。
- 标记已读时未读数 -1。
- 出现缓存不一致时，可通过数据库重新计算修正。

## 8. 联调步骤

1. 家属提交申请，管理员收到通知。
2. 管理员确认申请，家属和护工收到通知。
3. 家属新增任务，护工收到通知。
4. 护工标记通知已读，未读数减少。

## 9. 验收标准

- 通知只在站内展示。
- 未读数准确。
- 用户不能查看他人通知。
- 点击通知能跳转关联页面。
