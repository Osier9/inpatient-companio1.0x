# 阶段 11 管理员工作台开发文档

## 1. 开发目标

实现管理员登录后的工作台，聚合展示待审核申请、今日排班、服务中患者、在岗护工、超时任务、待处理留言和近期评价。

## 2. 输入与依赖

- 依赖阶段：阶段 04-10。
- 需求来源：ADM-001。

## 3. 数据库开发

本阶段不新增业务表。

读取表：

- `care_request`
- `care_service_order`
- `care_schedule`
- `care_task`
- `care_record`
- `service_message`
- `care_review`
- `caregiver_profile`
- `patient`

如性能不足，可使用 Redis 缓存：

- `dashboard:admin:overview:{date}`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `AdminDashboardController` | 工作台接口 |
| `DashboardQueryService` | 聚合查询 |
| `DashboardAssembler` | 组装前端展示对象 |

### 4.2 查询指标

- 待审核申请数。
- 今日排班数。
- 服务中患者数。
- 在岗护工数。
- 超时任务数。
- 待处理留言数。
- 近期评价列表。

### 4.3 业务规则

- 工作台只读，不修改业务状态。
- 超时任务以 `care_task.task_status=TIMEOUT` 为准。
- 待审核申请以 `care_request.request_status=PENDING` 为准。
- 在岗护工可按今日有排班或服务状态统计，V1.0 推荐按今日排班统计。

## 5. API 开发

必须实现：

- `GET /api/admin/dashboard/overview`
- `GET /api/admin/dashboard/pending-requests`
- `GET /api/admin/dashboard/today-schedules`
- `GET /api/admin/dashboard/timeout-tasks`
- `GET /api/admin/dashboard/unhandled-messages`
- `GET /api/admin/dashboard/recent-reviews`

## 6. 前端开发

### 6.1 页面布局

- 顶部指标卡片：
  - 待审核申请、今日排班、服务中患者、在岗护工、超时任务。
- 中部列表：
  - 待审核申请。
  - 今日排班。
- 异常区：
  - 超时任务。
  - 待处理留言。
  - 近期评价。

### 6.2 交互

- 点击待审核申请跳转申请详情。
- 点击今日排班跳转排班详情。
- 点击超时任务跳转任务或记录详情。
- 点击留言跳转留言详情。
- 无待办时展示“暂无待处理事项”。

## 7. 联调步骤

1. 构造待审核申请。
2. 构造今日排班。
3. 构造超时任务。
4. 构造留言和评价。
5. 打开管理员工作台检查统计和列表。
6. 点击列表项检查跳转。

## 8. 验收标准

- 管理员登录后默认进入工作台。
- 概览数据与业务模块列表一致。
- 无数据时展示空状态。
- 工作台接口只允许管理员访问。
