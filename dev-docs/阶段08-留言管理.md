# 阶段 08 留言管理开发文档

## 1. 开发目标

实现家属与护工围绕服务单的非实时文本留言，以及管理员查看留言和添加内部备注。

## 2. 输入与依赖

- 依赖阶段：阶段 05。
- 需求来源：BF-030 至 BF-033、FAM-009、CAR-007、ADM-009。

## 3. 数据库开发

新增迁移：`V009__message.sql`。

创建表：

- `service_message`
- `service_message_read`
- `admin_message_note`

关键索引：

- `idx_message_order(service_order_id, sent_at)`
- `idx_message_patient(patient_id)`
- `idx_message_sender(sender_user_id)`
- `idx_message_read(reader_user_id)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `FamilyMessageController` | 家属留言列表、发送留言 |
| `CaregiverMessageController` | 护工留言列表、回复留言 |
| `AdminMessageController` | 留言会话列表、详情、内部备注 |
| `MessageApplicationService` | 发送、读取、标记已读 |
| `MessageAccessService` | 校验家属和护工是否能访问服务单 |

### 4.2 业务规则

- 家属只能对已授权患者的服务单留言。
- 护工只能回复本人服务单相关留言。
- 管理员可查看全部留言。
- 管理员内部备注只对管理员可见。
- V1.0 不做实时聊天、不做语音、不做文件。
- 留言发送失败时，前端必须保留输入内容。

## 5. API 开发

必须实现：

- `GET /api/family/service-orders/{orderId}/messages`
- `POST /api/family/service-orders/{orderId}/messages`
- `GET /api/caregiver/service-orders/{orderId}/messages`
- `POST /api/caregiver/service-orders/{orderId}/messages`
- `POST /api/common/messages/{id}/read`
- `GET /api/admin/messages`
- `GET /api/admin/service-orders/{orderId}/messages`
- `POST /api/admin/service-orders/{orderId}/message-notes`

## 6. 前端开发

### 6.1 家属端

- 留言列表按服务单聚合。
- 展示最后一条留言、发送时间、未读数。
- 留言详情使用消息气泡。
- 文本输入框发送失败后保留内容。

### 6.2 护工端

- 留言列表只展示本人服务单相关会话。
- 详情页可回复文本。
- 不展示家属手机号。

### 6.3 管理端

- 留言会话列表。
- 留言详情。
- 内部备注输入区。
- 内部备注明确标识“仅管理员可见”。

## 7. 联调步骤

1. 家属发送留言。
2. 护工端出现留言会话。
3. 护工回复。
4. 家属端查看回复。
5. 管理员添加内部备注。
6. 家属和护工端确认看不到内部备注。

## 8. 验收标准

- 家属和护工不能查看无关服务单留言。
- 管理员内部备注隔离。
- 已读状态正确。
- 留言失败时保留输入。
