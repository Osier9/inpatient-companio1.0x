# 阶段 00 基础工程开发文档

## 1. 开发目标

建立前后端基础工程、公共规范和本地运行环境。本阶段不实现具体业务页面，只交付后续模块可复用的工程底座。

## 2. 输入与依赖

- 输入文档：`specs/02-technical-architecture/技术架构.md`、`specs/03-tech-stack/技术选型.md`、`specs/08-code-design/代码设计.md`。
- 外部依赖：JDK 17、Node.js、MySQL 8、Redis 7、MinIO、Docker Compose。
- 阶段依赖：无。

## 3. 后端开发步骤

1. 创建 Spring Boot 3.x 后端工程。
2. 建立包结构：

```text
com.inpatientcompanio
  common
  auth
  patient
  caregiver
  care_request
  schedule
  care_task
  care_record
  message
  notification
  review
  dashboard
```

3. 在 `common` 中实现统一响应：
   - `ApiResponse<T>`
   - `PageRequest`
   - `PageResponse<T>`
4. 实现统一异常：
   - `BizException`
   - `ErrorCode`
   - `GlobalExceptionHandler`
5. 接入 MyBatis Plus 和 Flyway。
6. 配置 Redis 连接。
7. 配置 MinIO 客户端 Bean，但本阶段不开放图片业务接口。
8. 建立审计日志基础能力：
   - `AuditLogEntity`
   - `AuditLogRepository`
   - `AuditLogService`
9. 建立健康检查接口：
   - `GET /api/common/health`

## 4. 数据库迁移

创建首个迁移文件：`V001__init_common.sql`。

必须包含：

- `sys_audit_log`
- `file_object`

所有表统一字段：

```sql
id bigint primary key,
created_at datetime not null,
updated_at datetime not null,
created_by bigint null,
updated_by bigint null,
deleted tinyint not null default 0
```

## 5. API 开发

必须实现：

- `GET /api/common/health`

响应示例：

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "status": "UP"
  }
}
```

该接口不需要登录，用于部署和本地环境健康检查。

## 6. 前端开发步骤

1. 创建 Vue 3 + TypeScript + Vite 工程。
2. 建立目录：

```text
src/
  admin/
  mobile/
  shared/
```

3. 建立三类布局：
   - `AdminLayout`
   - `FamilyMobileLayout`
   - `CaregiverMobileLayout`
4. 建立 Axios 实例：
   - 请求拦截 token。
   - 响应处理 `code !== "0"`。
   - 401 清空登录态。
   - 403 跳无权限页。
5. 建立 Pinia Store：
   - `useAuthStore`
   - `useAppStore`
6. 建立空路由壳：
   - `/admin`
   - `/family`
   - `/caregiver`

## 7. 配置文件

后端需要提供：

- `application.yml`
- `application-dev.yml`
- `.env.example`

前端需要提供：

- `.env.development`
- `.env.production`

环境变量至少包含：

| 变量 | 说明 |
| --- | --- |
| `DB_HOST` | MySQL 地址 |
| `DB_NAME` | 数据库名 |
| `REDIS_HOST` | Redis 地址 |
| `MINIO_ENDPOINT` | MinIO 地址 |
| `JWT_SECRET` | JWT 密钥 |

## 8. 联调步骤

1. 启动 MySQL、Redis、MinIO。
2. 启动后端服务，确认 Flyway 自动执行迁移。
3. 浏览器或接口工具访问健康检查接口。
4. 启动前端服务，进入管理员、家属、护工三个空布局。
5. 手动模拟 401、403、业务错误响应，检查前端错误处理。

## 9. 验收标准

- 后端启动成功。
- `GET /api/common/health` 返回统一成功响应。
- Flyway 可从空库执行。
- 前端可启动，并能访问三端空布局。
- Axios 可正确处理模拟 401、403、业务错误。
