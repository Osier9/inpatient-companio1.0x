# 阶段 10 评价管理开发文档

## 1. 开发目标

实现服务结束后家属评价护工，管理员查看和处理评价，护工查看本人评价且不展示家属手机号。

## 2. 输入与依赖

- 依赖阶段：阶段 05。
- 需求来源：BF-034 至 BF-036、FAM-010、CAR-009、ADM-010。

## 3. 数据库开发

新增迁移：`V011__review.sql`。

创建表：

- `care_review`

关键索引：

- `uk_review_order_family(service_order_id, family_user_id, deleted)`
- `idx_review_caregiver(caregiver_id)`
- `idx_review_rating(rating)`
- `idx_review_process_status(process_status)`

## 4. 后端开发

### 4.1 核心类

| 类 | 职责 |
| --- | --- |
| `FamilyReviewController` | 家属提交评价、我的评价 |
| `AdminReviewController` | 评价列表、详情、处理状态 |
| `CaregiverReviewController` | 护工查看本人评价 |
| `ReviewApplicationService` | 评价提交和状态处理 |
| `ReviewDomainService` | 评价权限、重复评价、服务单状态校验 |
| `CaregiverRatingService` | 刷新护工评分摘要 |

### 4.2 业务规则

- 服务单未结束不可评价。
- 同一服务单同一家属最多评价一次。
- 评价包含评分、标签、文字评价。
- 管理员可标记需回访、已处理。
- 护工端不展示家属手机号。
- 评价提交后刷新护工平均评分和服务次数。

## 5. API 开发

必须实现：

- `POST /api/family/service-orders/{orderId}/review`
- `GET /api/family/reviews`
- `GET /api/admin/reviews`
- `GET /api/admin/reviews/{id}`
- `PATCH /api/admin/reviews/{id}/process-status`
- `GET /api/caregiver/reviews`

## 6. 前端开发

### 6.1 家属端

- 服务结束后展示待评价入口。
- 评价表单：
  - 评分。
  - 标签。
  - 文字评价。
- 已评价服务单不再展示提交按钮。

### 6.2 管理端

- 评价列表：
  - 服务单、患者、护工、评分、标签、评价内容、提交时间、处理状态。
- 操作：
  - 标记需回访。
  - 标记已处理。

### 6.3 护工端

- 我的评价列表：
  - 展示评分、标签、文字、日期。
  - 不展示家属手机号。

## 7. 联调步骤

1. 将服务单置为已结束。
2. 家属提交评价。
3. 管理员查看评价。
4. 管理员标记需回访。
5. 护工查看本人评价。
6. 家属重复提交评价，系统拦截。

## 8. 验收标准

- 未结束服务单不可评价。
- 不可重复评价。
- 管理员可处理评价。
- 护工端评价脱敏。
