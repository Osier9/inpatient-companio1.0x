# 技术架构规格说明

## 1. 总体架构

住院陪护系统采用前后端分离单体架构。管理员 PC 后台、家属 H5、护工 H5 共用后端 API 服务，后端按业务领域模块拆包，使用统一鉴权、统一响应、统一审计和统一异常处理。

## 2. 系统组成

| 子系统 | 说明 |
| --- | --- |
| 管理员 PC 后台 | 陪护机构内部使用，处理管理、审核、排班、记录、留言、评价和工作台 |
| 家属 H5 | 患者家属使用，完成选护工、申请、查看任务记录、留言和评价 |
| 护工 H5 | 护工使用，完成看排班、确认任务、提交记录、回复留言 |
| 后端 API 服务 | 统一业务接口、权限控制、状态流转和数据读写 |
| MySQL | 主业务数据库 |
| Redis | 登录态、锁定计数、未读数、短期缓存 |
| 对象存储 | 保存任务执行图片 |

## 3. 后端分层

| 层级 | 职责 |
| --- | --- |
| Controller | 参数校验、角色入口、响应封装 |
| Application Service | 编排事务、跨模块协作、事件发布 |
| Domain Service | 业务规则、状态流转、权限边界校验 |
| Repository | 数据访问 |
| Infrastructure | JWT、Redis、对象存储、审计日志、定时任务 |

## 4. 模块架构

| 阶段 | 模块 | 后端包 |
| --- | --- | --- |
| Phase 01 | 账号与权限 | `auth` |
| Phase 02 | 患者与家属授权 | `patient` |
| Phase 03 | 护工管理 | `caregiver` |
| Phase 04 | 陪护申请 | `care_request` |
| Phase 05 | 排班管理 | `schedule` |
| Phase 06 | 陪护任务管理 | `care_task` |
| Phase 07 | 执行记录与图片 | `care_record` |
| Phase 08 | 留言管理 | `message` |
| Phase 09 | 站内通知 | `notification` |
| Phase 10 | 评价管理 | `review` |
| Phase 11 | 管理员工作台 | `dashboard` |

## 5. 权限架构

- 角色权限：ADMIN、FAMILY、CAREGIVER。
- 数据权限：
  - 家属只能访问已授权患者数据。
  - 护工只能访问本人排班服务单和患者数据。
  - 管理员可访问机构内全部业务数据。
- 图片权限：用户必须先通过业务权限校验，再获取短期图片访问地址。

## 6. 事件架构

后端通过应用事件解耦业务模块和通知模块：

| 事件 | 触发模块 | 消费模块 |
| --- | --- | --- |
| 申请提交 | 陪护申请 | 站内通知、工作台 |
| 申请确认/驳回 | 陪护申请 | 站内通知 |
| 排班变更 | 排班管理 | 站内通知 |
| 任务待确认/需调整 | 任务管理 | 站内通知、留言 |
| 任务超时 | 执行记录 | 站内通知、工作台 |
| 留言发送 | 留言管理 | 站内通知 |
| 服务结束 | 排班或服务单 | 站内通知、评价 |

## 7. 阶段架构推进

- Phase 00 建立工程、鉴权、响应、异常、审计、文件基础能力。
- Phase 01-03 建立基础主数据。
- Phase 04-07 打通申请、排班、任务、记录主链路。
- Phase 08-10 补充留言、通知、评价。
- Phase 11 基于前序模块做工作台聚合。
